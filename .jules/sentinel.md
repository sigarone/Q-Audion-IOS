## 2026-08-14 - Replace insecure UserDefaults token storage with Keychain
**Vulnerability:** Sensitive authentication tokens (`access_token`, `refresh_token`), `user_id`, and `device_id` were stored in `UserDefaults` via `QAudionAppState.swift`. `UserDefaults` is stored in plaintext inside the app's sandboxed `.plist` file, making these credentials vulnerable to extraction via unencrypted iTunes/Finder backups, jailbreaks, or file system access.
**Learning:** Even if `TokenVault` exists in the app layer for secure storage, duplicated credential persistence in the engine layer (`QAudionAppState`) using `UserDefaults` bypasses the security benefits. Both the App and Engine layers must independently enforce secure credential storage if they manage credentials.
**Prevention:** Always use iOS Keychain with appropriate accessibility attributes (e.g., `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`) for authentication tokens and device/user identifiers, never `UserDefaults`. Ensure UI state view models in shared modules correctly implement this instead of taking shortcuts.
